# 第1章×第2章「お金の性格、答え合わせ」UI Pilot

更新：2026-10-12。状態：**V3.2専用プレビュー・ユーザー未承認・FROZENコア非変更**。

## 目的

第1章で得たJOB／4STYLEと、第2章で回答した家計12カテゴリの満足・必要性・確認項目を、**本人の回答の範囲で**つなぎ、「価値観の重なり」や「本人が確認したいこと」を一つ返す。自分の性格が数字で「当たっている／間違っている」を証明したり、架空の一致率を付与したりしない。

## 実画面への組込み

- `Chapter12AnswerCheckCard.tsx` と `chapter12-answercheck-card.css` を新設。
- `ResultScreenChapter2V32.tsx` の公式JOBカード**直後**、未鑑定の宝箱より**前**に一枚設置。
- `MudagiriAppV2.tsx` は **`?chapter2v32=1&chapter12check=1`** の両条件を満たす場合に限り匿名IDを渡す。通常の第2章には表示しない。
- カード内では「ムダギリくんの会話→条件に合う発見1つ→次に確かめる1つ→根拠を見る」の順。2件目は折りたたみ。
- 本人IDが違う、第1章未完了、家計12カテゴリ未完了、無効カテゴリ、ステータスの不備は**カード非表示**。
- 全カテゴリがあるが裏付けの組合せなしの場合は「一致を決めつけない」小さな中立カードにする。
- 診断コア（第1章3軸/STYLE分類、第2章12カテゴリ判定・confirmedA・cUpper）、GAS、LINE、直接面談CTA、既存SNS画像は未変更。
- 既存IDをイベント/GASへ別途書き出さない。第1章性格診断の専用GASへ家計データを送らない。共有カードへ答え合わせの内容を追加しない。

## スマホで見比べるテスト用ページ

- `chapter12-answercheck.html`（隔離デモ入口。noindex）
- `src/chapter12-answercheck-preview.tsx`：既存の本物の `ResultScreenChapter2V32` を架空の第1章・第2章データで描画し、**7ケースを切替**。
  1. ENJOY × 満足/保護した娯楽
  2. ENJOY × 本人が見直したい娯楽
  3. DRIVE × 目的ある自己投資
  4. OPTIMIZE × 未使用・解約可能サブスク
  5. SECURE × 共通点を出す根拠がない（推定禁止）
  6. 別ユーザーの匿名ID（カード非表示）
  7. 家計が11/12カテゴリしかない（カード非表示）
- 実際のユーザー入力・GAS送信・個人情報を使わない。面談予約はテストページでは無効。

## 技術監査

- 安全性エンジン：`scripts/chapter12-answercheck-experiment-v1.mjs`
- 根拠・同一人物・未完了ガード：`scripts/qa-chapter12-answercheck-experiment-v1.mjs`（50件の独立テストでPASS）。
- UI動作：`scripts/qa-chapter12-answercheck-browser.mjs`（Chrome/WebKit × 320/375/390/430px、実C2カード位置・結果/根拠展開・非表示ケース・画像・水平スクロールを監査）。
- CI：`.github/workflows/qa-chapter12-answercheck-ui.yml`（`npm run build`、V3.2回帰QA、独立検証、モバイルE2Eを実行）。
- **CIの成功を確認するまで、ブラウザQAをPASSと主張しない。**
- JS/TSやHTML・CSSだけでは実機タップ感/可読性、現実のユーザーの驚きとCVの質は証明できない。

## 体験面の不採用条件

- 答え合わせを「一致率◯％」と誤解する／子ども・保険・旅行等の嗜好を勝手に創作する。
- 「直感型は浪費」「安心型なら保険を買うべき」といった金融商品への誘導。
- 中身が単なる第1章の性格説明の再掲で、本人が新しい確認ポイントを説明できない。
- 家計結果の見出しが遠くなって第2章の大切な戦果やライフプラン相談CTAが見つけにくくなる。
- ガード不成立の利用者に架空の一致結果を作る。根拠がないときにカード全体を消す方がよいかはUXテストで判断する。
