## 2. 合成データによる反証テストの主な束

| 束 | 代表的な確認 | 狙い |
|---|---|---|
| 住まい | 同じ目標で住居カテゴリを`inspect`→`protect`へ替えると最初の一手が変わる | 第2章を単なる文言の飾りにしない |
| 住まい×時期 | `near`→`far`で契約時期の確認→長期の環境条件に変わる | 「時の塔」の新情報が結果を変える |
| 挑戦×C | 未確定候補Cあり→Cなしで「候補は元手でない」の注意と一手が変わる | Cを確定資金にしない |
| 教育・老後 | 教育費/娯楽の`protect`あり→なしで、今守りたい支出との関係が変わる | 大切な支出を無条件で削らない |
| C1 STYLE | ENJOY→DRIVEで説明のタグだけ変更、金融適性は変わらない | 第1章の性格を過大解釈しない |
| 収入アップ | 昇給、社外での依頼、学習の手がかりで最初に調べる対象を変更 | 必要時1問の情報価値 |
| 資産形成 | 近い出費あり/なし/未定で、予定額の確認、残す資金の条件、使途の確認へ分岐 | 商品適性を推定せず資金使途を分ける |
| 不正データ | 匿名ID不一致、12カテゴリ欠落/重複、A/C合計不一致、Aの不正な付与、`na`に金額、非有限値 | 第1・第2章の意味を壊す入力は拒否 |
| 共有 | 金額・時期・本人の悩みを共有プレビューへ含めず、共有には明示同意を要求するフラグ | バズより先にプライバシー |

**現実の反論**：上記分岐がコード上で違っても、本人の生活において「もっとも効果的な行動」が本当に選ばれたとは限らない。**金融・転職・資産形成の最適解や商品適合性を診断する機能ではない**。
