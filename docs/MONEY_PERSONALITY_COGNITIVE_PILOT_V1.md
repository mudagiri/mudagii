# MONEY PERSONALITY COGNITIVE PILOT V1

Status: **PILOT PROTOCOL / NOT FROZEN**  
Target: **5〜8名**  
Route: `?adaptive=money-type&cognitive=1`

## 目的

このPilotは統計的妥当性を証明するものではない。公開Adaptive版を実際の人が触ったときに、以下の問題をField Pilot前に発見する。

1. 質問の意味が意図どおり伝わるか
2. A/Bや5段階が回答可能か
3. CORE→Adaptive→Separatorが不自然に感じられないか
4. JOB / Style / Resultに「自分っぽさ」があるか
5. 測っていないことをResultが勝手に言っていないか
6. 30問＋必要な追加質問の負担が許容できるか
7. Resultのどこに共有価値があるか
8. 家計診断への遷移理由が成立するか

## テスター構成

5〜8名の中で、できるだけ以下を混ぜる。

- お金を普段からよく確認する人 / 必要な時だけ確認する人
- 比較して決める人 / 感覚を重視する人
- 将来準備をする人 / 今の機会も強く重視する人
- 家計管理に詳しい人 / 詳しくない人

職業・年収・投資経験で均一化しない。今回見るのは「専門知識」ではなく、質問解釈とResult体験。

## 実施手順

### 1. 事前説明（30秒）

参加者には次だけ伝える。

> お金の知識テストではありません。正解はありません。普段の自分に近い方を選んでください。質問で気になることがあれば、画面下の「テスト用メモ」だけ押してください。診断中は詳しい感想を説明しなくて大丈夫です。結果が出たあとにまとめて聞きます。

**診断中に回答理由を逐一しゃべらせない。** Concurrent think-aloudで回答そのものが変わるのを避け、基本は通常利用に近い状態を保つ。

### 2. 診断中

Cognitive modeだけ、各設問で任意の4フラグを記録できる。

- 意味が取りづらい
- 両方当てはまる
- どちらも合わない
- 似た質問に感じる

フラグを押さなかった質問は問題なしと断定しない。回答時間、戻り、Result後の聞き取りと合わせて見る。

### 3. Result閲覧

結果が出たら、すぐ質問せず**30〜60秒は本人に自由に読んでもらう**。

最初に本人が見た場所、スクロール順、スクショしたい箇所、家計診断CTAへの反応を観察する。

### 4. 画面内Debrief

「テスト用フィードバック」から以下を1〜5で回収する。

- JOB名の自分っぽさ
- Result全体の当たり感
- 質問の理解しやすさ
- 診断の長さ
- Separatorの自然さ（発生者のみ）
- 誰かに見せたいか
- 家計診断へ進みたいか

加えて、

- スクショしたい箇所
- 一番自分っぽかった箇所
- 一番違った箇所
- その他コメント

を回収する。

### 5. 口頭インタビュー（5〜10分）

画面内回答後に、次の順で聞く。

1. 「結果を見た瞬間、最初に何を思った？」
2. 「一番“自分のことっぽい”と思ったのはどこ？」
3. 「逆に違うと思ったところは？」
4. 「JOB名だけ友達に見せたとしたら、どう説明する？」
5. 「主属性・副属性は意味が伝わった？」
6. 「3軸のうち、分かりづらかったものは？」
7. フラグを押した質問だけ表示し、「この質問をどういう意味だと理解した？」
8. 「診断があと5問長かったらどう感じる？」
9. 「この結果ならスクショする？するならどこ？」
10. 「家計診断へ進むとしたら、何が知りたいから？」

質問は誘導しない。「本当はこういう意味なんだけど」は回答を聞き切るまで言わない。

## 自動保存されるもの

通常Public payloadとは別に、同じPilot sinkへ `PUBLIC_COGNITIVE_DEBRIEF` として保存する。

- parentSessionId
- participantId
- JOB / Primary / Secondary
- Result Content Version
- Separator数
- 設問ごとのフラグ
- 設問のvisitCount / totalViewMs
- 7評価
- スクショ候補
- 自由記述

Cognitive payloadのsession idは `通常sessionId__cognitive`。通常診断データと1対1で追跡できる。

## レビュー基準

N=5〜8なので、平均点だけでFROZEN判断しない。以下を赤信号として扱う。

### 質問

- 同一設問に「意味が取りづらい」が**2人以上** → 文面を必ず再監査
- 同一設問に「どちらも合わない」が**2人以上** → シーン/選択肢の網羅性を再監査
- 同一設問に「両方当てはまる」が**3人以上** → 弁別性を再監査
- 同一ペア・同一概念に「似た質問」が**3人以上** → CORE/Reserve重複を再監査
- 説明を聞くと想定constructと別の意味で答えていた → 最優先修正

### Result

- JOB fit 1〜2 → その人の因子プロファイルとJOB copyを個別照合
- Result fit 1〜2 → 「どの文が外れたか」を必ず特定
- 同じResult文が複数人から違和感 → テンプレを修正
- INTUITION=衝動、PERIODIC=放置などの未測定推論に読めた → 即修正
- Secondaryを「自分の強い特徴」と誤読 → 相対順位表現を再調整

### UX

- 3人以上が明確に「長い」と発言 → 問題数ではなく、どの区間から長く感じたか特定
- Adaptiveが「同じ質問の繰り返し」に感じられる → Reserve wording / 演出を再監査
- Separatorの意図が理解できない → 文言を修正。ただしFactor Scoreには入れない原則は維持
- Result到達前に離脱意向が出る → 進捗/演出/文章密度を先に直し、測定項目削減は最後

## Pilot後の意思決定

修正を3段階に分ける。

### A. すぐ直す

誤解、文法、意味不明、未測定推論、UI不具合。

### B. Field Pilotまで保留

「なんとなく似ている」「どっちでもいい」など、統計で識別力・cross-loadingを見るべき項目。

### C. 触らない

1人の好みだけによるJOB名・世界観・表現変更。n=1で構造を動かさない。

## Cognitive Pilot完了条件

- 致命的な意味誤解が残っていない
- Public flowが5〜8人全員で完走
- Resultの低納得ケースについて原因説明ができる
- 問題設問の修正候補が明文化される
- Field Pilotで検証する論点が一覧化される

ここまで終わったら、**RPG最終デザイン / 計測本番化 → Field Pilot**へ進む。
