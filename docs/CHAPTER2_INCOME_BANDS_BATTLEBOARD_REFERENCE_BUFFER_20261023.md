# 第2章｜2026-10-23 iPhone実画面フィードバック・設計是正

## 結論
単身世帯の年収600万円以上を一つにまとめること、最優先候補しか見えず12カテゴリの戦況が一覧で分からないこと、負担率差・見直し候補・確認済み改善額の概念が混在することが課題。

### 今回、画面に実装するもの
- 第2章入口の単身本人額面年収を `400未満/400–499/500–599/600–699/700–799/800–999/1000以上/わからない` に明示。複数人の家計全体収入の質問と混同しない。既存の600万円以上の過去回答は旧データとして継続読込（必要時のみ再選択）。
- 第2章リザルトでも入口の単身年収回答を自動引継ぎ。**選択した年収帯の年齢×額面年収×勤労者の公表セルが見つからない場合、「同条件平均」や具体的な平均負担率を作らない**。600万円以上単一の2025年の参考値を「600–699」「800–999」「1,000以上」の年齢別平均と称して流用しない。
- 宝箱の最優先候補の後に、**12カテゴリ全部の「斬る／整える／守る／見極める」などの戦況を2列で表示**。ボタンで、展開した詳しい比較一覧へ直行できるようにする。確定改善額・見直し候補上限・判定は一切変更しない。

### 重要：本人の割合と同年代の公式参考率から生じる差の扱い
- 本人負担率 `p_user = 対応する本人支出 / 月手取り ×100`
- 公式参考率 `p_peer = 同じ公式公表セルの費目平均支出 / 同じセルの平均可処分所得 ×100`
- 数値の比較 `g = p_user - p_peer`（pt差）。原表所得帯が幅なら各公式元セルの率の範囲を表示。
- 仮に公式参考率の上端より本人率が大きければ、`gap_monthly=月手取り×max(0,p_user-p_peer_upper)/100` という**統計との差の月額換算**は計算可能。ただし**現実に節約できる額でも、契約の見直し余地でもない**。地域・世帯人数・費目範囲の違いが原因かもしれない。
- **「改善できる可能性のバッファ」**として使えるのは、金額の上乗せではなく*追加確認すべき支出が潜んでいる可能性と優先順位*。もし金額を表示する場合、「統計上の差の円換算（非節約額）」を既存 `Chapter2PeerComparisonCard` に独立表示する。
- `confirmedA` は本人回答により具体的に確認できた改善額、`cUpper` は診断の未確定候補。公表負担率差はどちらにも加算しない。住宅費などにある別人口・別範囲の参考額（例：同一都道府県・住居形態のみ）から差を作り、「同年代・同年収帯のバッファ」と表示しない。
- 将来的に実際の契約内容を取りに行き、同じ費目範囲で削減策が確認できた場合に**追加の未確定候補へ昇格する余地**はある。ただしその際も既存 `cUpper` と重複した金額の二重計上を防止するデータ契約・反証・QAが必要。

### 4視点での設計原則
- 行動経済学：`最初の1件→12項目の戦況一覧→必要な詳細` で認知負荷を抑え、全体像を失わせない。公式データの条件確認は後段に集約、デフォルトで年収の再質問をしない。
- 心理学：守る支出・学ぶための自己投資も結果に含む。比較差は「あなたが無駄遣いしている証拠」と言わず「他にも見ておきたい領域」という非審判的フレームで示す。
- マーケティング：初期の大きな未確定上限に依存するのではなく、同年齢・所得帯の比較が成立した理由と1つ目の確認アクションによる納得感を作る。LINEクリックはCVではなく、予約完了をCVとする。
- バズ理論：シェア画像はJOB・称号・クエスト達成を中心に、年収・支出金額・統計との差を載せない。友人にも診断体験自体を薦めやすくする。

### 事実確認：2024年公表原表
2024年全国家計構造調査第1-29-1表の単身世帯・世帯主30～39歳・勤労者の、抽出済み2024年50万円階級で年収600–649万円に概数標本50世帯を確認。一方で650–699万円階級は採択基準n>=50の元セルとして収録されていない。従って600–699万円階級全体の同条件平均を元表セル1つで代用しない。600+という以前の広い区分を400–499等の年齢交差率の延長で使うこともしない。
