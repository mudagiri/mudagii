## 最上位ゴールと成功基準
**North Star：第1章結果閲覧者あたりの、検証可能なライフプラン相談面談予約数。**
家計診断への遷移、公式LINEへの移動、SNSシェアはすべて**中間指標**。クリックだけで予約や友だち登録が成立したとみなさない。

候補指標（分母は原則、同一匿名ブラウザIDで重複除外した初回のResult閲覧）:
- 主指標：面談予約**確定** / Result閲覧。予約フォームや予約管理側の一次データと突合できる時だけ使用。
- 先行指標：家計クエスト開始 / Result、家計クエスト完了 / 開始、LINE公式への遷移クリック / Result。
- LINEの実CV：**友だち追加完了** / Result。外部遷移クリックからは推定しない。
- 拡散ガードレール：共有メニュー起動 / Result、共有画像の受渡し・保存 / Result、流入再訪 / シェア表示。Web Share APIのキャンセル・テキストだけ投稿は別物。
- UX品質：モバイル別のResult到達深度、CTAが表示された比率、SNS別メニューの展開率、誤操作戻り、WebKitでのターゲットサイズ。

既存の `money-type-funnel-v1.ts` は**ローカルStorageのみ**であり、ユーザー横断のCVRやヒートマップとは扱えない。まず本番GASの接続、プライバシー設計、リード追跡の同意・最終CV計測を設計する必要がある。家計診断コアは変更しない。

## リリース前の必須条件
1. 第1章V18のBuild、390px Chrome／iPhone WebKit、タップ領域・オーバーフロー・CTA干渉のUI QAがPASS。
2. 専用Money Personality GASのGET健康確認・実Sheetの受信確認。現在GitHub `pilot-hidden-preview`環境では `MISSING_ENDPOINT`。
3. 本番予約・LINE追加の「確定CV」計測基盤。既存SNSやLINE利用者の個人情報を本人同意なしに診断DBと連携しない。
4. LINE特典のガイドPDFが実際に配布可能になってから、配布を確約するCTAへ移行。公式LINEへの外部URLは別途あり、`LINE_URL`はまだ空。
5. 実施するA/Bは端末・流入別に割付を維持し、**予約確定率を主要指標**、シェア到達率や家計診断完了率をガードレールに設定。結果の解釈時は検証サンプルの偏り・標本数・信頼区間を明記。

## A/B実験計画（実装・開始は保留）
- 実験A：「旧黒CTA / ゴールドCTA + 文脈依存Dock」。全要素一括にすると何が効いたか分からないので、可能ならCTA色/追従を順番にテスト。
- 実験B：「SNS５並列 / 画像共有１つ＋SNS選択アコーディオン」。SNS別到達だけでなく、Result→家計とResult→予約の両方を追う。
- 実験C：「LINE特典の要点→登録 / 家計診断の直進」。ガイド配布実稼働後に開始。コピーの誠実性と参加者の自律性を守る。
- 1つの端末でテスト対象が頻繁に切り替わらない安定した割付が必要。測定環境が揃うまで『CVRが何％改善』と宣言しない。
