## 0. P0の結論

**Draft 0.5の「いま一番何を確かめたい？」→「まずそれを確認しよう」はリザルトの自己反復に陥る。ここを放置して画像制作やUIに進むことはNO-GO。**

8件の架空ケースを厳格に判定すると：

- **価値がありそうな仮説：2件**（先行章との関係が次の行動を本当に変える可能性）
- **条件付き：3件**（本人の回答と結びつくが、まだ一言の助言が当たり前／必要な情報が足りない）
- **不合格：3件**（回答を言い換えただけ、または第3章ならではの価値を生まない）

上記は編集者による**仕様監査の定性的な分類**であり、利用者の診断精度・満足度・面談CVの実績ではない。しかも「有望」2件も本人に刺さるか実証していない。

**改善すべき問いは「本人は何を確認したい？」ではない。冒険で新たに取得する価値があるのは、まず \`goalHorizon\`（いつごろ叶えたいか）、必要時に \`friction\`（何が阻害するか）。** 現実の条件とC2で確認済みの「守るべき価値／確認できた改善機会／未確定候補」を結び、**手段が目標を壊すトレードオフを先に明らかにする**ことが第3章ならではの発見になりうる。

## 1. 内容品質の評価基準

数値による採点は**設計レビューのチェック項目**で、実測ではない。4視点の合計点を無理につくらない。各例を以下の条件で**良い／条件付き／不合格**に判定。

| 観点 | 合格基準 | 典型的な失敗 |
|---|---|---|
| 新しい関係が見えるか | C1のJOB/STYLE、C2の実結果、C3の目標/時期/壁の**関係を説明**し、答えの復唱を超える | 「資産形成に興味がある→資産形成を考えよう」 |
| 判断に使えるか | 今日できる1行動と、別の選択肢を優先する条件が明確 | 「とりあえず考えてみよう」で終わる |
| 前章と一貫するか | C1の自己理解を上書きせず、C2の\`confirmedA\`は**条件確認済みの見直し機会**、\`cUpper\`は**未確定** | C2の参考上限を貯金・投資資金にする |
| 提案の正当性 | 独立した根拠（目標・本人の意思・前章の実データ）と未確認情報を区分 | 2つの本人選択があるだけで金融適合性を断定 |
| 面談への接続 | 実際に担当できるテーマと、面談で一段具体化できる内容が一致 | キャリア斡旋・稼げる保証・具体商品の適合保証 |
| 行動経済学 | 追加回答の情報価値が、認知負担に見合う | 結果をほぼ変えない設問を必須にする |
| 心理学 | 保護している価値を尊重し、答えに矛盾があっても人格評価しない | 「資金がない→計画性が低い」 |
| バズ理論 | 本人が誇れる冒険記録は表示可能。**障害・家計金額は非公開** | 相談すべき弱みが共有カードに載る |

### 必須の「非反復テスト」

**E2の回答文字列を削除しても意味が通るようなリザルトは、E2で得た情報を真に使えていない**可能性が高い。  
**C1またはC2の出力を取り除いても「その人に特有の提案」が全く変わらなければ、第3章として前章との連続性が弱い**。

このテストは「C1/C2の語を無理やり差し込む」という意味ではない。根拠にならないC1/C2は使わず、**このケースは連携情報だけでは差別化できない**と判定する。

## 2. 架空ケース8件：入力→弱い結果→修正案→結論

**ケースはすべて架空**。C1のJOB/STYLE、C2のステータス/金額はデザイン監査用の仮入力。コード出力・実人物の財務情報とは区別する。

### A｜「老後に備えたい」×「今の楽しみは守りたい」
- **仮の前章事実**：C1 STYLE=ENJOY。C2 娯楽カテゴリは本人が維持したいと評価し、削減確定の根拠はない。C2目標「老後」。
- **Draft 0.5式の回答**：最初に確かめたい＝「いつまでに、何を目指すか」。
- **弱い出力**：「老後の期限を確認しよう」。本人の回答を言い換えたに過ぎない。
- **修正結果の仮説**：
  > **「楽しみを削るか、老後に備えるか」ではなく、まず両立する時期を決めよう。**
  >
  > 第2章では楽しみの支出を守りたいと答えた一方、目指す先には老後の安心がある。今の満足を削る前に、何歳ごろからどんな備えが必要かを考える順番なら、両方を尊重できる。
  >
  > **今日の一手**：備えを使い始めたい年齢を一つ書き出す。
  >
  > **まだ未確認**：必要額、現在の資産と負債、他に使う予定のあるお金。
- **面談テーマ**：暮らしの楽しみを守る資金計画（ライフプランでも資産形成でも可）。
- **反証**：ユーザー自身が娯楽支出を減らしたい場合は「守る」が最優先でなくなる。
- **判定：条件付き**。価値の両立という着眼はあるが、老後資金計算には時期と資産情報が不足。本人が「すでに考えている」と言えば新しい発見ではない。

### B｜「収入を増やしたい」×「見直し機会はあるが実行前」
- **仮の前章事実**：C1 STYLE=OPTIMIZE。C2にサブスクの条件確認済み改善機会が**月1,800円（架空）**、停止・実現は未確認。C2目標は未選択。
- **C3入力**：収入増を希望。障害＝時間が足りない。
- **弱い出力**：「時間がないから副業ではなく、効率よく稼ごう」——実際に可能か不明。
- **修正結果**：
  > **収入を増やす道を探すなら、「使う時間を増やさずできること」から条件を確かめよう。**
  >
  > 収入増が目標で、今は時間を増やすのが難しいという回答がある。第2章には見直し機会もあったが、まだ実際に使える収入としては扱えない。
  >
  > **今日の一手**：本業の昇給条件を一つ確認する。
- **面談テーマ**：収入・働き方・資金目標（実際に扱える範囲を明示）。
- **反証**：すでに昇給余地がない、職場情報が本人の希望と違う場合は別の道へ。
- **判定：条件付き**。本人の「収入増・時間不足」だけでほぼ同じ結果になる。C2の見直し情報が**主提案を変えていない**ため、前章連携の新しい価値はまだ弱い。

### C｜「時間を増やしたい」×「第2章の数値は未確定」
- **仮の前章事実**：C1 STYLE=DRIVE、C2には未確定候補のみ（\`confirmedA=0\`）。時間・仕事の実測データなし。
- **C3入力**：「自由時間を増やしたい」＋「時間が足りない」。
- **弱い出力**：「時間を大切に、忙しい予定を減らそう」。
- **修正できる範囲**：「『増やす』より時間の使い方を先に確認」は一般論で、個別の発見とは言い切れない。
- **判定：不合格**。C1のDRIVEで仕事時間が長いとは判断できず、C2家計結果で本人の時間配分は分からない。
- **次に必要な確認（必要時のみ）**：「何に時間を取られやすいか（仕事/家事/移動/その他/不明）」。実際の時間数を捏造しない。データ取得しても深い適職診断にしない。

### D｜「資産形成を始めたい」×「前章の目的地だけが連携」
- **仮の前章事実**：C2 goal=\`invest\`、C1未連携、12カテゴリ詳細未連携。

### E｜「家族の将来に備えたい」×「教育費は守りたい」
- **仮の前章事実**：C1 は本人確認済みだがJOB内容は今回の結論に使わない。C2「子どもの教育費」は本人が必要として守る判定。C2 goal=\`family\`。

- **弱い出力**：「教育費を貯めよう」——今の支出と今後の必要額を混同。
- **修正結果**：
  > **今払っている教育費と、これから必要になる教育費を分けて考えよう。**
  >
  > 第2章では現在の教育費を必要な支出として守った。家族・教育が目的地なら、その支出をムダと扱うより、いつ増える可能性があるかを確かめる方が次の一手になるかもしれない。

- **面談テーマ**：教育費の時期と家計の負担整理。
- **反証**：これ以上教育費が増えない状況なら現在の契約やその他の目的へ変更する。
- **判定：条件付き**。今払うお金/将来必要なお金の区別は価値があるが、次の進学があることや金額は未確認である。本人の実データでテストが必要。

- **仮の前章事実**：C2 goal=\`home\`。住居費カテゴリに「見直し/比較条件確認」の状態があるが、削減額は未確定（比較差を実現可能額としない）。

- **弱い出力**：「住まいの費用を見直そう」——第2章の繰り返し。
- **修正結果**：

  >
  > 第2章で住居費は確認対象だった。ただし家賃の平均との差は削減可能額ではない。住まいが今回の目的地なら、住み続ける期間によって今の契約を見直すべきか、次の住まいに備えるべきかが変わりうる。
  >

- **面談テーマ**：住まいの選択肢／家計への影響（ローン審査確約はしない）。
- **反証**：転居の余地がない、借入・家族条件が厳しい場合は結論が変わる。
- **判定：有望（設計仮説）**。C2の「確認対象」とC3の「住まい」・「期限」の関係が、単純な節約から住まいの選択順序へ変わる。実ユーザーにとって新しいかは別途テスト。

- **仮の前章事実**：C2 goal=\`challenge\`。C2は**未確定候補\`cUpper>0\`のみ、\`confirmedA=0\`**。C1 JOBは何でもよい（適職判定に使わない）。

## 3. 本監査が促すコンテンツ変更（Draft 0.6提案）

### 結論：「最初に何を確認したい？」という設問の再検討

今の第3章E2は**結果の行動を先に答えさせている**。結果で同じことを返すならユーザーに発見がない。

**新しい候補**：「時の塔／どの時間軸で叶えたい？」という1判断。目標の具体的な期限を問うのではなく、最初はざっくりとした時間軸だけを取得する。

ムダギリくん（仮）：  
> 「目的地は見えてきたね。**いつごろ、その景色にたどり着けたらうれしい？**」

- \`near\`：「1〜3年以内」
- \`middle\`：「4〜10年くらい」
- \`far\`：「10年以上先」
- \`unknown\`：「まだ分からない」

これは**本人希望の期間**であり、投資商品の適合性、資金の使える時期、運用可能期間と同義ではない。住居・教育など選択された目的地によって時間帯は補助コピー調整が必要。

**3章をRPGとして成立させるための変化**：本人が時間軸を選ぶと、目的地の灯りが地図上で遠近・道の長さとして変化。**選択→地図が変わる→結果の最初の一手に必要な時期情報が反映**される。世界観は第2章のドットRPG、画像は別制作。

### QUEST構成の変更候補

1. **Prologue**：本JOBとC2の戦果を引継ぎ、門から出発。
2. **QUEST 1 願いの旗**：C2目標が検証済みなら確認、なければ選択する。
3. **QUEST 2 時の塔**：希望を叶えたい時期を1つ選ぶ（近い／中くらい／先／未定）。
4. **QUEST 3 霧の関門**：**必要な場合だけ**何が一番の障害か、または短期資金の使途、収入と時間の制約など、結果を変えるための補足を一つ確認。一般的な「何を確かめたい？」の4択は破棄。
5. **QUEST CLEAR 未来の作戦書**：保護/未確定/確認済みのC2事実と「目的地×時期×実際の制約」を組合せた一手。面談予約は一つ、本人がテーマ選択を変更できる。

## 4. 面談CVの検証（3ケースの固定タイプへ戻さない）

**共通CTA候補：**「この作戦を相談する」。**個別の相談理由**：
- 住まい：賃貸継続と住まいの見直し時期を整理。
- 挑戦：実際の初期費用と使える資金を区分（提供できる範囲に限定）。
- 老後：今の楽しみを守りながら、必要な時期と金額を整理。
- 教育：今の教育費と将来の教育費を時期別に整理。
- 増収：今の働き方の制約と目標収入を整理（職業斡旋・報酬UPを保証しない）。
- 未定：何を考えると前に進めるか、本人の優先事項を整理。

**事業上の必須条件**：実際に面談で扱える専門領域と担当者が対応可能な範囲を確定する。収入増をテーマにした面談でも、転職斡旋できないならその期待を煽らない。LINEは友だち追加だけで**面談予約完了ではない**。初期追跡は\`CTAクリック→LINE/予約導線→日時確定→実施\`の各段階で識別する必要がある。
