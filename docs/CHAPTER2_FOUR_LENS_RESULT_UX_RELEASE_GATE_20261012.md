# 第2章リザルト｜4視点を設計・実装・QAまで貫通させる受入ゲート

更新日：2026-10-12／対象：第2章「改善できるかも」の内訳と戦果順序、Draft PR #46／本番未採用。

## ユーザー指摘を最上位の問題定義にする

「改善できるかもの詳細が先に先に出てくるかつ詳細タップしないとみえないだと不親切」「4つの視点が毎度抜けとる」。

旧版は「大きい未確定額 → JOB/性格答え合わせ → 宝箱 → 未来の年額 → 戦果 → 保険 → 相談 → 敵図鑑」で、各カテゴリの**金額・理由・次の行動を知るには下までスクロールして敵図鑑のタップが必要**だった。ユーザーが実際に判断するための根拠を意図せず隠しており、インパクトより信頼と理解を優先する再設計が必要。

### 4視点：必ず「何を変えたか」「QAで何を証明するか」「未実測」の3層に分離する

| 視点 | 必須UX原則 | 今回の実装 | QAで保証する項目 | 人間の実験が必要なもの |
|---|---|---|---|---|
| 行動経済学 | 金額だけのアンカリングを避け、選択材料を同じ場面で提示。余計なタップを必須にしない | 月最大額の直後の宝箱に `CANDIDATE_BREAKDOWN`。全 `cUpper>0` カテゴリを金額・条件と確認方法付きで最初から表示。主な次の一手を1件に絞る | 全件表示、理由・確認事項の行内表示、タップ不要、未確定0円なら非表示 | ユーザーが根拠を自力で説明し、確認先を選べるか |
| 心理学 | 驚きと安心のバランス。罪悪感・恐怖・誤認の誘発を抑える | 各行で「月額・未確定」表示、上部の「削減は未確定」、比較差≠ムダの注記。好きな支出を「削るべき」と言わない | すべての候補に未確定表示、確認理由、参考上限の注記、金額がない時は架空の累計を出さない | 「必ず削れる」「平均より高いから浪費」と誤解しないか |
| マーケティング | 金額の驚き→理由による納得→継続したらどうなるか→本人の行動→必要なら相談、の一貫した導線 | `POTENTIAL_HERO → POTENTIAL_TREASURE → CANDIDATE_BREAKDOWN → FUTURE_REWARDS → JOB/答え合わせ → 戦果 → 保障の棚卸し → 相談`。相談CTAは残し、保険加入などへ誘導しない | 上記のDOM表示順、既存相談CTA保持、全件内訳をCTAより前、1/5/10年の条件・金額の保持 | 有効実面談CV／100開始者と納得感。CTAクリック数だけで成功判断しない |
| バズ理論 | 自分で説明できる発見を作りつつ、本人の金額をシェアしない | 「宝箱の中身＝敵＋金額＋確認事項」で理解可能に。SNS画像は従来のJOB/クリア記念のみとし、内訳・保険・家計金額・診断IDを除外。クリック強制なし | 既存の `createQuestShareCard` の金額非同梱・既存シェアUI/ボタン・プライバシー回帰 | 実際に人に話したくなるか、共有率が上がるか（現段階は未測定） |

## 正しい第2章の順序

1. 第2章QUEST CLEAR：未確定の月最大額と注意書き、1/5/10年へ直接ジャンプできる。
2. 宝箱と**全候補内訳**：候補ごとに敵の画像/カテゴリ、月最大の参考上限、その条件（通信費基準・比較目安など）、「まず確認すること」。確認に別タップを要しない。
3. 未来の戦利品：**未確定候補 `cUpper` のみ**を12/60/120倍。全額を毎月改善して継続できた場合という条件と保証しないことを隣接表示。確定額を加算しない。
4. 第1章から引き継いだJOBと「お金の性格、答え合わせ」：金額の理解を妨げない位置に移す。性格の一致率を創作しない。
5. 戦果報告と `confirmedA` （確定基準が厳しいので主役にしない）、保障の棚卸し。保障は全STYLE共通だが「保障内容を把握済み or 1年以内に確認済み」なら出さない。保障の余地を金額加算しない。
6. ライフプラン相談CTA：ユーザーの意思決定・プライバシー優先。
7. 敵図鑑：全12カテゴリの詳細。**最初の候補の理由を知るために開く必要はない**。
8. シェア：家計金額・個人情報なし。

## 開発・リリースの不可侵ルール

- FROZENの第1章・第2章診断エンジン、基準データ、`confirmedA`／`cUpper`の算定、GAS、LINE、相談実績集計は変更しない。
- `CANDIDATE_BREAKDOWN` へ掲載するのは`cUpper>0`のカテゴリのみ。既存の`vm.rows`の値と`nextAction`を再利用する。平均/基準の差額全額を勝手に上乗せしない。表示はあくまでも未確定。
- 候補0円なら数字も内訳もねつ造しない。最大金額の合計と内訳は同じ`vm.rows`／`vm.potential.cUpper`に基づく。カテゴリ表示に丸め誤差があり得ることを理解し、値を作り足さない。
- 画面上の「理由」は候補抽出方法（`cMethod=mobile/standard/wide`）の短い説明。将来のシミュレーションは実際の節約額でも利回り予測でもない。
- CSSは既存の暗いRPG戦果の雰囲気、敵画像、ムダギリくんを継承し、320px以上でも13px前後で判読できるようにする。
- `qa-chapter2-v32.ts`：SSRで全候補、全件理由・次の確認、順序、ゼロ候補、将来額の非合算・シェア保持を確認。
- `scripts/qa-chapter12-answercheck-browser.mjs`：ChromeとWebKit各320/375/390/430px、タップなしで全候補が読み取れること、横スクロールなし、表示順、将来額のジャンプ、既存答え合わせ・保険案内・相談・シェア回帰。
- 公開リビジョンを照合し、Chrome/WebKitの実画面検証が通るまでは「実装・公開PASS」を主張しない。
- **4視点それぞれに少なくとも一つの観察可能な実装条件と、対応するQAかPilot質問がない変更はレビューを完了させない**。

## 合格判定の留保

今回の自動QAは**コード上の表示条件**を保証するだけ。理解率、信頼、離脱、拡散、実面談へのCVに関する数字は取れていない。5〜8名のCognitive Pilotで理解・誤認を自由回答で確認し、その後に実際の面談につながった数をベースラインと比較する。証拠なしの「4視点で100点」は禁止する。
