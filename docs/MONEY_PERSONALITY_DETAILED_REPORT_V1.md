# お金の性格診断｜詳細レポート設計 V1

更新日: 2026-10-09

## 0. 位置づけ

通常Resultを薄い無料版にしない。通常Resultは単体で「これ自分だ」「誰かに見せたい」が成立する完成品とする。

詳細レポートは、通常Resultの文章を長くしたものではなく、**なぜその行動パターンが出るのか／どう扱うと強みになるのか**を分解する取扱説明書とする。

- 通常Result = 感情に刺さる人物像・具体シーン・共有
- 詳細レポート = 判断構造の分解・場面別の応用・自分の扱い方
- 家計診断 = 実際の支出データで改善余地を確認する実戦

性格診断の結果は、家計診断のbenchmark、ムダ判定、改善額を変更しない。

## 1. 通常Resultに残す情報

通常Resultは以下を削らない。

1. JOB + STYLE のアイデンティティ
2. 刺さる一文
3. 日常の「あるある」2件 + 任意で4件
4. 本人と周りの見え方のズレ
5. 強み / 行きすぎた時 / 整え方
6. 近いTYPE・対照TYPEとの比較
7. 3軸の簡易表示
8. 代表的なNEXT MOVE
9. シェアカード

共有カードには、タイプ名・STYLE・短い一文に加えて**代表的な具体シーンを1つ**まで載せる。収入、残高、支出額などの個人金融情報は載せない。

## 2. 詳細レポートで初めて深掘りする情報

### A. あなたのお金タイプの全体像
- JOBとPrimary STYLEの組み合わせ
- Secondary STYLEが補助的にどう効くか
- 「典型像」と「あなたのスコアで少し違う部分」

### B. 3軸の深掘り
各軸について以下を分けて説明する。

- 相対方向: FUTURE / IMMEDIATE など、どちら寄りか
- 絶対強度: HIGH_HIGH / LOW_LOW / MIXED
- バランス状態: CLEAR / LEAN / BALANCED
- Separatorの有無
- その組み合わせが判断にどう表れやすいか

「未来寄りだから計画的」など、軸から測っていない人格特性へ飛躍しない。

### C. STYLEの組み合わせ
- Primary STYLEが最初に見るもの
- Secondary STYLEが最後のひと押しで効く場面
- 2つが同じ方向を向く時
- 2つがぶつかる時

### D. お金を使うまでの意思決定フロー
1. 何に反応するか
2. どこで一度止まるか
3. 何を確認するか
4. 最後にGO / NO GOを分けるもの
5. 決めた後に納得しやすい条件

通常Resultの「あるある」を再掲するのではなく、複数シーンに共通する**判断構造**を説明する。

### E. 場面別の出方
以下は診断結果から説明可能な範囲だけを使い、「このカテゴリに必ず使う」と断定しない。

- 大きな買い物
- 定期課金・固定費
- 急な誘い・予定変更
- 比較対象が多い買い物
- 将来につながる支出
- 不安や不確実性が高い場面
- 「欲しい」と「やめた方がいい」がぶつかる場面

### F. 強みの取扱説明書
- 強みが活きる条件
- 強みが裏返る条件
- オーバードライブのサイン
- 1分で戻す方法
- 継続しやすい管理方法

### G. 家計診断とのクロス解釈
第2章完了後だけ表示できる追加レイヤー。

- 性格Resultと実際の支出を混同しない
- 「このTYPEだからこの支出がムダ」とは言わない
- CONFIRMED saving、benchmark差、改善候補の意味を変更しない
- 実際の家計結果に対して、**続けやすい攻略方法**だけをTYPEに合わせて変える

例:
- 同じ改善候補でも「毎月細かく見る」より「更新日に確認」が合う人
- 「削る」より「守る支出を先に決める」方が動きやすい人

## 3. レポートの推奨構成

1. COVER / あなたの32TYPE
2. 1ページ要約 / あなたを一言でいうと
3. 判断の設計図 / 3軸
4. 価値観の優先順位 / Primary + Secondary STYLE
5. お金を使うまでの5ステップ
6. 6つの場面別パターン
7. あなたの武器
8. 武器が暴走する時
9. 自分に合う整え方
10. 家計診断クロス分析（第2章完了者のみ）
11. 30日攻略プラン
12. 診断の読み方・注意事項

## 4. UX原則

- 通常Resultの読了を詳細レポート閲覧の必須条件にしない
- 詳細レポートを見ないと自分のTYPEが理解できない設計にしない
- 未提供状態で「受け取れる」「今すぐダウンロード」などのCTAを出さない
- PDFでもWebでも、スマホで1ブロックずつ読める構造にする
- 文章量ではなく「新しい理解が増えるか」を密度の基準にする

## 5. データ・安全ガード

詳細レポートで使ってよい情報:
- Money Personalityの回答から確定した10因子・3軸・STYLE・JOB
- 分類Confidence / Separator利用情報
- 第2章完了後に明示的に連携された家計診断の確定結果

使わない／推測しない情報:
- 未取得の収入・資産・職業・家族構成
- 性格タイプから推測した浪費カテゴリ
- 医学的・臨床的性格特性
- 「必ず」「絶対」などの確定的行動予測

## 6. 実装境界

Resultコードには、詳細レポート本文を先に詰め込まない。
詳細レポートは将来、Resultとは別のcontent layerとして実装する。

推奨:
- `detailedReportV1.ts` = レポート構造と生成
- `detailedReportScenesV1.ts` = 場面別説明
- `detailedReportHouseholdBridgeV1.ts` = 第2章クロス分析
- 通常Resultの `resultV9Content.ts` / `resultV10Insight.ts` は共有・共感の役割を維持
