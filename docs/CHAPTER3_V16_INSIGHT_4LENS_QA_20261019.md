## 結論と現段階
独立プレビューの自動検証は可能。まだ有効面談率・「当たってる感」の実測検証は完了していない。公開URLはGitHack経由の一時検証であり正式ホスティングではない。Vercel既存チームへのアクセスは403のため勝手に更新しない。

## ロジック監査
- 有効回答は6×4×4×7×5＝3,360通り。8称号すべてに到達可能なことを機械的に確認。
- `undecided` は家計・返済の切迫回答を除き、未定の目標を勝手に具体化しない。
- `skip` は障害がないという証拠として使わない。
- `notYet` / `unknown` が、障害なし・未回答という理由だけで `expand` に昇格しない。
- `confirmedSavingMonthlyJPY`、`reviewCandidateUpperMonthlyJPY`、`goalAmountJPY`、`gapJPY` は、前章未連携の独立デモでは常にnull。
- 別章の結果を推測・再判定することも、資産運用の適合性や借入可能額の判定も行わない。

## リリース前の残タスク（V1.6単体 → 三章統合）
1. 専用ホストでの永続プレビュー。Vercel権限を持つ担当者が接続を確認、または明示された別ホストを構築する。GitHackは暫定。
2. 実機iPhoneで文字・背景・操作を目視する。ブラウザエミュレーションのQAを「実機完了」と書かない。
3. 第1章JOB/STYLEと第2章12カテゴリの「データの出所・一致・同意・保存期限」を契約化したうえで、確定改善額／未確定候補を別表示で受け渡す。正本・判定ロジックは変更しない。
4. 相談の流れは「何が分かる・何が変わる」→ 本人同意 → LINEまたは予約の接続。架空の連絡先、未確認の外部URLは禁止。
5. 5〜8人の非誘導Cognitive Pilot。「どこが自分らしい？」「新しく分かったことは？」「次に何を確かめる？」「この先どうしたい？」を質問。困りごとの自己開示を強要しない。
6. 実CVの効果は、第2章直相談と第3章経由の有効面談実施率比較を行って判断。小サンプルの印象を統計的な改善証明としない。

## QAの合格範囲
GitHub Actions専用ワークフローで(1)純粋関数と全組み合わせ、(2)Viteビルド、(3)Chromium/WebKit 320/375/390/430pxの5問→結果→詳細→戻る、(4)外部GitHubソースCDNの操作までを確認。自動QAのPASSはユーザーへの心理的な有効性や成約率を保証しない。
