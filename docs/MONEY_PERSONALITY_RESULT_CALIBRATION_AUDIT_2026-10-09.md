# 第1章：JOB分類と結果文の心理監査（2026-10-09）
対象: 第1章のみ。家計診断のFROZENコアは変更しない。

## コードで確認できた課題
- UIはスコア比率で「バランス」を独自判定していたが、エンジンはスコア差（7.5 / 15）で判定していた。たとえば100対85はエンジンではCLEARなのに画面は「バランス」になる。
- 32TYPEの冒頭2場面に仕事道具・ホテル・ライブ・保険・二軒目が登場するケースがあり、未測定の生活習慣と本来の性格評価を混同させるおそれがあった。
- 拮抗する軸やSTYLEでは最後の追加設問で近い側を選ぶが、もう一方の特徴も残る。その説明が結果画面になかった。

## 修正内容
1. 結果ラベルはエンジンの`balanceState`/`absoluteState`を使用。相対グラフの位置は0–100スコア差から対称に描画。
2. 拮抗時はムダギリくんが「両方の特徴が近かった」と説明。タイプを断定しすぎない。
3. 32 TYPE×6シーンの文章と種類を一切削除せず、冒頭2シーンだけ生活経験への依存が小さい順に調整した。分類は変更なし。
4. 日常場面はあくまで例と明記。読者がすべてを経験している前提で書かない。
5. 自動QAで100対85、LEAN、HIGH_HIGH、LOW_LOW、32TYPE×6シーンを検証。

## 残る実証課題
- 仮想10,000人の数値は回答生成仮説に依存する。日本人のタイプ分布や共感率の実測ではない。
- 境界付近でJOBが変化する懸念は引き続き存在する。今回は判定閾値を勝手に変更していない。
- 「俺かも」を実証するにはタイプ名を隠して自分と近接タイプの説明を比較するブラインドテストが必要。
- 5～8人のCognitive Pilot→30～50人の追加検証で、自己一致度・他タイプ識別率・生活場面の不一致・共有意欲を確認する。
