## 結論

- **監査で発見した最優先問題**: 同じ年代・年収の細分化区分を選んでも標本不足時に「なぜ表示されないか」が即時には分からず、バグ・未反映と誤認しやすかった。
- 対処: 所得区分選択の直下に、**利用可能／確認が必要／標本等の条件不足**の3段階フィードバックを追加。ARIA `role=status`, `aria-live=polite` で操作後の状態を伝える。
- **誤読防止**: 2024年勤労者世帯の参考は世帯主の年齢・就労形態の一致が必要。チェックボックスを「何を確認するか」を先頭にして言い換え。
- **単身の誤期待を解消**: 年収600万円以上を含め、単身の全所得帯で同年代参考があるかのような見出しをやめ、「年収帯の参考と比べてみる」に統一。条件が揃った区分のみ同年代比較。
- **数値**: 2024年原表二人以上高所得セルは12件。標本数50未満・非公表・区分不一致はfail-closed。単身高所得は該当セルなし。
- **配信**: GitHub Pagesの既存preview publisher（main）は2026-10-18時点 `feat/chapter2-result-v32-possible-rewards-20261011` を参照。**本改修リリースブランチとは異なるため、旧previewのURLを最新版と称さない**。Vercel連携は権限エラー403でこの対話からは公開確認できない。
- **公開判断**: 技術QAと公開QAを別扱い。GAS本番シークレット未設定ゲート、独立一次ソース照合、実機iPhoneのビジュアル承認は未解決のまま本番適用禁止。

## 4視点監査

| 視点 | 原因・損失 | 対策 | 検証 |
|---|---|---|---|
| 行動経済学 | 未表示の原因が分からず「無効操作」に見える。複数選択による認知負荷 | 任意の細分化選択直後に状態表示。条件一致時だけ年齢・就労確認、対象外には質問を増やさない。 | 合成データで3区分と確認ゲート切替をChrome/WebKitで試験 |
| 心理学 | 同年代で比べられないことが自分の不適合・診断精度不足に見えやすい | 「公表データの条件不足」という理由を表示。高所得でも「ムダが多い／少ない」と断定しない | 30代1500万円以上（概数n40）→非表示＋理由文 |
| マーケティング | 比較結果を見ないまま離脱、または比較差を削減保証と勘違い | 『自分に近い世帯と比べる』と顧客価値から始める。実際の比率は費目カードへ。確定改善額・未確定候補・面談CTAを分離 | データフロー上 `confirmedA`/`cUpper`/LINE引継ぎに参考額を加算しない回帰 |
| バズ理論 | ひと目で伝わらない比較は共有されず、所得・支出額の外部共有は抵抗がある | 共有カードは従来のJOBキャラ中心。所得区分・公的統計の数値を勝手に共有素材へ加えない | 既存SNS共有テスト維持 |

## 比較の数学的意味・注意

- 公的参考負担率 = 同一交差セルの**費目平均支出 ÷ 平均可処分所得**。個々の世帯の割合の分布ではない。
- 2024年の年齢×所得交差集計と2025年の所得帯だけの参考を平均・混同しない。
- 本人の手取り月額は入力値、公的統計の「平均可処分所得」は別の定義・調査対象。厳密な意味で家計が完全一致することを保証しない。
- 額面年収・世帯主年齢・就労状況の確認は**参考表示専用**。情報収集のためにLINE等へ送らない。
- 比較平均との差 = saving ではない。確定削減額は `CONFIRMED` 証拠がある項目のみ。

## QA合格条件

1. 年収細分化の未選択時、同年代負担率が**自動表示されない**。
2. 世帯主年齢 / 勤労者世帯のどちらか未確認時、負担率を表示しない。
3. 入力に対応する原表n<50区分は**表示しない**。同じ位置でその理由が分かる。
4. 対象の年代・所得・世帯区分・原表出典の一致、3費目の率一致。
5. 支出額・比較率・LINE共有テキスト・面談CVの漏えいなし。テスト環境から外部へデータ送信なし。
6. Chrome / iPhone相当WebKitの操作試験。幅320/390/430pxの横スクロール防止。
7. 既存第1章→第2章導線、JOB/STYLE引継ぎ、12カテゴリ、面談CTA、SSR共有の非退行。
