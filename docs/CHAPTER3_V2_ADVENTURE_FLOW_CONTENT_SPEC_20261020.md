## 0. 意思決定：冒険の面白さと診断の意味を先に成立させる

**仮コンセプト：「未来の航路をひらく」——第1章で得たJOB、第2章で持ち帰った家計の戦果を携えて、まだ見えない未来への最初の道を見つける。**

第3章の一つの約束は「自分にとって次に検討する価値がある一手と、その理由が分かる」。

* RPGは世界観の装飾ではなく、**プレイヤーの選択で物語の状態が変化**するための仕組み。
* ただし、「危険な橋を渡る → 金融リスクに強い」のような短絡推定は禁止。
* 「稼ぐ・育てる・整える」は**表に出す3職業／3タイプではない**。リザルト3ケースの検証軸に留める。
* 第1・第2章の結果が信頼できる形で渡らなければ、デモでは未連携と伝える。架空JOB、家計の改善金額・融資可能額を作らない。
* 事業CVは**共通「面談予約」**。ユーザーが相談したいテーマは個別。第2章から面談直行できる導線は維持する。
* 結果以外の画面は**標準スマホで原則1画面／1イベント**。低い画面・文字拡大ではアクセス可能性を優先してスクロールを許す。
* **背景画像・イベントの物体・ムダギリくんの追加ポーズは、内容がFIXした後で個別に制作**する。UI全部を焼き込んだ画像を作らない。

## 1. なぜ3イベント案を暫定第一候補とするのか

次の3候補を比較した。スコアは**定性的な設計仮説、実測値ではない**。

| 構成 | 体験価値 | リザルトの証拠 | 無駄な回答負担 | 暫定判断 |
|---|---|---|---|---|
| 旧版：未来の希望を5つ質問 | 低い（アンケート化） | 希望の言い換えに偏る | 中 | 不採用 |
| 3つの道（稼ぐ／育てる／整える）を最初に選ばせる | 選びやすい | 「自分で選んだ方向」を返すだけ | 小 | 不採用 |
| **物語：目的地→旅の資源→試練→作戦書** | 高い可能性 | 希望・使える資源・選択基準が別々に得られる | 小〜中 | **検証用第一候補** |
| 分岐10本以上の大型RPG | 高くなる可能性 | 必要な情報は増えない可能性 | 大 | MVP不採用 |

この候補でも、本当に情報が足りなければイベント追加や結果内容の修正を検討。**「3」を固定しない**。

## 2. 物語の全体アーク

**冒険の内部状態を3つだけ持つ。**
1. **行き先の灯り** \`destination\`：何を叶えたいか（未来の優先方向）。
2. **携える道具** \`usableResource\`：いま無理なく使えそうなもの（本人申告、未検証）。
3. **霧の中の判断** \`decisionStyle\`：不確かな場面でまず何を確かめたいか（ゲーム内選択、金融適合性とは別）。

UI上の進行は**光る目的地→装備した道具→開ける進路**。選択の直後に各アイテムが地図上に反映される。リザルトは「上記3つ＋第1/2章の事実から決めた次の一手」、という流れ。

### Prologue：ギルドの門から出発する（操作1つ）

**場面**：第2章の家計クエストをクリアした冒険者がギルドを出る。ムダギリくんがギルドの扉を開く。遠くの大陸は霧で見えない。

ムダギリくん（仮）：
> 「ここまで来たね。自分の戦い方も、家計の戦果も手に入れた。でも、まだ決まっていないことがある。**その力で、どこへ向かう？**」

演出：第1章で取得した本当のJOBがある場合のみJOB名と正本画像を表示。第2章の本当の確定改善が確認できる場合だけ数値を区別して使う（未確定候補は戦果扱いしない）。未連携プレビューでは「引き継ぎ準備中」。

プレイヤーの操作：**「未来の地図を開く」**。この画面では個人情報を聞かず、説明を増やさない。

報酬：霧に覆われた地図が現れる。3つの地点だけが描かれている。

### Event 1：「灯台に浮かぶ未来」（主に未来の優先方向）

**目に見える状況**：夜の海。灯台の光が4方向に伸びる。目的地として見えるのは「今の暮らし」「大切な人と時間」「新しい可能性」「将来の安心」。誰でも選択でき、「まだ決まらない」を逃げ道として置く。

ムダギリくん（仮）：
> 「あの光、全部が未来につながっている。**今の君がいちばん守りたい景色はどれ？**」

選択肢ラベル（暫定／言い換え要検証）：
- 「今の暮らしに余裕がほしい」 \`livingRoom\`
- 「好きなことに使う時間を増やしたい」 \`freeTime\`
- 「やりたいことに挑戦したい」 \`challenge\`
- 「先々の安心をつくりたい」 \`security\`
- 「まだ一つに決められない」 \`unknown\`

**使う情報**：本人の希望の優先順位。これだけで稼ぐ／育てる／整えるを判定しない。「時間を増やしたい」は副業適性や年収不足の証拠ではない。

**選択直後の視覚変化**：地図に選んだ方向の灯台／旗が点灯する。次の画面でも、その色と選択名が引き継がれる。

### Event 2：「補給所の旅支度」（主に今使える資源）

**目に見える状況**：次の航路に進むには補給所で携えるものを決める。机の上に「時間を使うための時計」「手元の資金を分けるための金貨袋」「経験やスキルを生かす道具」「まだ判断しない白紙の地図」がある。**選ぶ物は投資元本を確定する仕組みではない**。

ムダギリくん（仮）：
> 「目的地は見えてきた。じゃあ、**いま無理なく使えそうなのは何だろう？** まだ分からないのも立派な情報だよ。」

選択肢：
- 「少しなら時間を使えそう」 \`time\`
- 「使い道を考えられるお金があるかも」 \`funds\`
- 「経験やスキルを生かせそう」 \`skills\`
- 「今は余裕がない／まだ分からない」 \`notSure\`

**使う情報**：本人が感じている活用可能資源（自己申告）。「あるかも」は**資金余力を確認したことにはならない**。第2章のCONFIRMED改善額があってもそれが現預金・運用可能額と一致すると推定しない。借入可能額や信用力はここで推測しない。

**選択直後の変化**：選んだ道具を地図の持ち物枠に追加する。第1章の本JOBによって違う小さな語りかけを用意できるが、「あなたの職業なら～が得意」は断定しない。

**要検証**：このイベントはRPGらしい反面、単に「何が使える？」というアンケート化リスクがある。Cognitive Pilotでは、選択肢が現実に即しているか、3問でも多く感じるかを重点観察。場合によっては第2章の正規データで情報が足りるケースを省略する。

### Event 3：「霧の分かれ道」（主に判断プロセス）

**目に見える状況**：目的地までの道が霧で消えた。前方に古い橋、地図の欠片、周回路。ユーザーは「危険か安全か」だけを問われるのではない。どの手順を最初に取るかを選ぶ。

ムダギリくん（仮）：
> 「道が見えなくなった。**最初に何を確かめてから進もう？**」

選択肢：
- 「まず道を調べる」 \`checkRoute\`：条件・情報を確認したい
- 「小さく試せる道を探す」 \`trial\`：取り返しのつく行動から始めたい
- 「いま持つ道具を見直す」 \`repack\`：資源と制約を整理したい
- 「目的地をもう一度確かめる」 \`revisitGoal\`：優先順位を確認したい

**使う情報**：決断の順番を表すゲーム内選好。投資リスク許容度、価格変動耐性、職業適性、収益性を判定しない。

**演出上の分岐**：選択により霧の晴れ方とムダギリくんの短いセリフが変わる。同じゴールに向かうが通る細道が違う。分岐後に新しい質問を無制限に追加しない。**選択肢の正誤・優劣は作らない**。

**重要な問い**：この選択によって現実の次の一手が必ず変わるべきではない。**結論は現実の目的と制約を優先し、ゲームの選択は結果の「進め方」「最初のアクション」や納得感の説明を調整する**。

### Quest Clear：「未来の作戦書が完成」（結果のみ縦スクロール）

画面上部の報酬は、JOBの上位職ではなく**「未来の作戦書」**。これまでに拾った①目的地の灯り、②使えそうな道具、③霧の中で選んだ道を、1枚の地図へ組み込む。

**リザルトの見出しは固定3タイプ名よりも、「○○から確かめてみよう」という実行可能な提案を優先**。第1・第2章から取り出した根拠と今回の選択に基づく**理由2つ以上**を示す。

結果の構造：
1. **戦果：** 実際のJOB（本人データがある場合）、第2章の確定改善と未確定候補の区別、今回の3選択から生成された地図。
2. **次の一手：** いま本人が着手できることを動詞付きで1つ。
3. **その理由：** 検証できる入力からの根拠2点（「あなたは～の性格」と断定しない）。
4. **必要なら別の道：** 主提案に対する反例となる条件を1つ表示。
5. **「まだ分からないこと」：** 本人の意思決定を逆転させうる未確認情報を1～2点に絞る。
6. **面談導線（共通CV）：** 「次の一手を相談する」等。押した後に相談したいテーマを選択可能にする。面談で得られる価値はケース別。面談に行かなくても行動1つ。
7. **任意の共有：** 第1章のJOB/STYLEと冒険ルートの共有に留める。借入・家計・金額・心理的な弱点は共有しない。

## 3. 冒険を「ただの質問」に戻さないルール

| 誤ったUI／演出 | 採用すべき体験 |
|---|---|
| 質問見出し→選択肢→次の質問 | 場面提示→起きた出来事→ムダギリくんの短い対話→選択→結果の視覚変化 |
| 選択しても何も変わらない | 地図上に光・道具・足跡が残る。次の場面で反映される |
| 長い心理学的な解説 | ユーザー本人が感じ取れる短いセリフと、リザルトでの根拠説明 |
| 「危険な道」を選ぶ→株式が適合 | 現実の余力を確認していないため商品適合性は判定しない |
| 3つの金融タイプを見せて選ばせる | 自分の目的・資源・判断順序を選ぶ。優先アクションの仮説は最後に |
| ストーリーが増えるほど面白い | 短くて意味のある選択だけ残す。不要な設問は削除 |

### 文章のトーン
- ムダギリくん：仲間として声をかける。「一緒に考えよう」「こっちも道はある」。
- 評価語や説教を避ける：「正解！」「さすが」「あなたは浪費癖がある」「怖がりだから」等は禁止。
- カタカナの金融ワードを序盤に詰め込まない。「リスク許容度」「信用力」「運用利回り」等は必要な場合のみ結果詳細で。
- イベントの場面を伝える1文は**意味のある状況**。長い説明をスクロールさせない。
- 第1・第2章と違って「お金を得る／バトルで敵を倒す」章ではなく、**自己発見と選択の章**。

## 4. 判定思想・ケースマッピング（現時点はロジック未確定）

**重要：3イベントだけでは、具体的な金融・キャリアの最適選択を判定するデータは足りない可能性が高い。** 目的は、本人が最初に「何を調べる価値があるか」の優先仮説を返すこと。

### 判定フロー（固定スコアではなくルール検証用）
1. \`destination\` から目標を得る。第2章から現実の家計情報があれば出典区分とともに確認。第1章のJOB/STYLEは本人の自己理解を補助する。
2. まず**現実の緊急性**を確認する。生活・返済・当面使うお金に不足が確かな場合、稼ぐ／投資以前に安全と資金確保を優先する。実際の生活余力が不明な場合は「不明」とする。
3. \`usableResource\` が \`skills\` / \`time\` かつ本人が稼ぐ道を望み、現実の条件が大きな障害でない場合に限り、「収入増の選択肢を一つ調べる」という**探索の提案候補**を作れる。ただし収入増が確実とは言わない。
4. 目標に使う時期が遠い可能性があり、生活防衛・負債・余裕資金を**別途確認する必要がある**なら「育てる準備として使う予定のお金を仕分ける」等を提示。将来商品の適合性を断定しない。
5. 制約が大きい、本人の目標が未定、確定情報が不足している場合は「まず判断材料をそろえる」とするが、**何を確認するか具体的に1つ**示す。
6. \`decisionStyle\` は提案の**実行プロセス・言い回しの補助**にのみ使い、稼ぐ／育てる／整えるの大分類を直結させない。
7. 複数の道が同等に有力なら、**1つに偽装して断定せず**「仮の第一候補」「これが確認できれば結論が変わる」と示す。面談はここを整理する選択肢。

### 追加で必要となる可能性がある最小データ
- 目標の期限が第2章からは得られない場合、Event 1の後で**任意の単一補助問い**を足すか、結果で未確認にする。
- 稼ぐことを優先したいかは、\`destination\` の4択だけでは分からない（自由時間を望むこと≠収入を増やしたい）。本人の意向が未確認なら「転職／副業に向く」とは示さない。
- 第2章のCONFIRMED改善は現金余力ではないため、資金を増やす商品の提案には別途生活防衛・負債・投資経験等の確認が必要。
- 本人の優先順位が不明なら、実際の利用データとPilotを踏まえてイベント構成を修正する。**結果が崩れるなら3イベントにこだわらない。**

### 反証テスト（最低限）
- 高所得・時間不足・資金余力はあるが自由が欲しい→「収入を増やす」が押しつけにならないか。
- 低所得・貯蓄なし・借入返済負担大→「資産運用を推す」と誤認させないか。
- 金融知識豊富・すでに運用中→「今から積立を始める」が陳腐にならないか。
- 第2章にCONFIRMEDなし、参考上限のみ→「資金を作れた」と表示しないか。
- 無回答／未定を複数選択→「何が不足か」さえ分からない薄いリザルトにならないか。
- 第1章で挑戦的JOB、今回の選択は慎重→矛盾を「あなたは矛盾する性格」と人格診断せず、目的に応じて判断が異なると中立表示できるか。

## 5. 4視点の監査（**毎回別個に適用**）

| 観点 | 設計基準 | よくある失敗 | 必ず確認する観測点 |
|---|---|---|---|
| **行動経済学** | 1場面1決定、選択負担を抑え、結果がすぐ景色へ反映。行動コストを少なくする | 何でも解放・5択連続で疲れる。選択肢を善悪に見せて回答誘導 | 各イベント離脱率、戻り率、選択にかかる時間、複数候補への迷い |
| **心理学** | 人の自律性を尊重。「未来」「使える資源」「判断順序」を本人が語れる。正解を押し付けない | 性格ラベリング、根拠のない断定、目標未定への恥の刺激 | 自分の言葉で結果の根拠を再現できるか、新しい気づきを一つ答えられるか |
| **マーケティング** | 面談前に価値を体験。結果別に相談すると得られるものを明確にする。第2章から直行も維持 | 予約誘導のために情報不足を人為的に作る。面談で解決できないテーマを約束 | 第2章完了者あたりの予約率、面談実施率、面談内容との期待一致、導線ごとの離脱 |
| **バズ理論** | 自慢・自己表現できる旅の記録を用意し、共有時は機密を除外 | 個人の家計、負債、弱みを晒す。全員同じ称号で共有する意味なし | 「誰に、何を見せたいか」を本人に聞く。共有意向/実共有の差を観測 |

**特に重要**：4視点の高評価でも、金融上の判断が間違っている／第2章の数値意味論が崩れるなら採択しない。UX採点とデータの正しさを同列にしない。

### 画像に焼き込まないもの（CSS/DOM必須）
- 日本語の見出し・吹き出し・設問テキスト・ボタン・結果金額・JOB名・選択状態・進捗・地図の分岐線・紋章の光・粒子・霧のオーバーレイ。
- 理由：テキスト校正・端末サイズ・多言語・音声読み上げ・第1章からの引継ぎ・ABテスト・データ整合性を維持するため。

### 画像制作の発注条件
1. **コンテンツと画面構成が採択されてから**制作する。
2. 第2章の公式ドット感／配色／線の粗さ／ムダギリくんの設定を実画面・既存ファイルで確認し、**勝手に別キャラへ変えない**。現在の画像生成の美麗イラストを正本にしない。
3. 画面全体を1枚の画像にはしない。文字なし背景、必要な物体の透過PNG/WebP、既存公式キャラの再利用という三層で考える。
4. 背景の必要枚数は**最大5シーンの候補**であり、先に共通背景の差分・CSSのみで済むかを比較して減らす。透過物体や新ポーズは不足が確定したときのみ個別制作。
5. デザイン責任の境界：場面イラストは世界観／遠景、CSSは情報構造／装飾／動き、キャラは会話の感情を担当する。
6. スマホ1画面内で主役が読め、選択肢が操作可能。背景だけで意味のある文字を表さない。低い端末では自然なスクロールを許す。

## 7. MVPのQA・検証計画

**コンテンツ→紙芝居／文字プロトタイプ→最少の画面実装→アセット**の順。現在は内容を検討するフェーズ。

- **設計レビュー**：5〜8人にストーリーだけ見せ、「設問を答えた」か「冒険した」か、目的／資源／判断の違いが分かるか、「次の一手」の理由に納得できるかを観察。
- **判定ロジック作成前**：実際の第1章データ契約と第2章12カテゴリの結果契約を確認。集計・確定額・候補額が混ざらない不変条件を書き出す。
- **完走確認**：3イベント+リザルトのうち「離脱が多い画面」「誤タップ」「戻る」「修正」「未定」「何も持っていない」を検証。
- **反実仮想**：同じ第3章の選択で、第2章の確定改善だけ変えたら必要な一手と理由が妥当に変化するか。逆に第2章が未連携でも架空の状況を作らないか。
- **ビジネス**：第2章から直接予約できる現行導線と、第3章を任意追加した導線で「第2章完了者あたり面談予約数」「実施率」「担当テーマ一致」を比較。章3のCTAクリックだけで成功と言わない。
- **画像QA**：CSS/背景/ムダギリくんを別々に差し替え可能か、既存第2章と世界観が同じか、文字と背景のコントラスト、モーション抑制、320〜430pxおよび小さい縦寸法、音声読み上げ。

### GO / NO-GO ゲート
- ① 3つのイベントがアンケートの言い換えを超えた**選択体験**になっている。
- ② 本人がリザルトで**「なぜこの一手か」**を2つ以上の証拠で追える。
- ③ 稼ぐ／育てる／整えるのうち1方向を**無理に選ばせていない**。
- ④ 第1/2章の事実を捏造・混同していない。
- ⑤ 面談のテーマが実際に対応可能で、予約前に本人の期待を調整できる。
- ⑥ 画像制作の必要性・枚数・公式ムダギリくんの不足ポーズが**コンテンツから逆算**で説明できる。

## 8. 未決論点と次タスク

**未決：** Event1で本当に一番知りたい「何を叶えたいか」が取れるか。Event2が「道具を選ぶだけのアンケート」に戻らないか。Event3の判断プロセスがリザルトに十分な新規情報を与えるか。ゲームの3回答で「稼ぐ／育てる」方向を選ぶには情報不足か。第2章のどのキーを公式に引き継ぐか。

**次タスク（優先度順）**
1. Event1〜3を「本人が実際に選べる内容」「結果に必要な情報」「選択後の見た目」の3点で**1シーンずつ赤入れ**。無駄な選択を削る。
2. **3つの仮リザルト**（稼ぐ可能性／育てる準備／判断材料整理）へ、どの選択×どの第1/2章の事実を使うか具体的に対応付ける。現実情報がないケースは未確認のまま留める。
3. 反証ケースを最低6ケース作り、リザルトの断定・相談先の不一致・第2章数値の意味の逸脱を検査。
4. Cognitive Pilot → コンテンツの採否 → アートディレクション規格 → 画像の制作リスト確定 → CSS/UI実装。
