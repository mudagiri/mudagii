# ムダギリ診断 第3章V2｜4視点「100点仕様」に向けた実装赤入れ Draft 1.0

2026-10-21 JST / **PR #77だけの隔離試作。内容FROZENではない。第1・第2章の診断コア・main・本番Pages変更なし。**

## 結論

**「4視点100点仕様」を名乗る条件は満たしていない。** ただし今回のコード変更によって、リザルトの内容品質を妨げていた3点に具体的な手を入れた。

1. **旧：** 未来の目的地と時期をリザルトで復唱して終了 → **新：** 前章の根拠が確認できた場合は「どちらが先か」「何を守るか」という*関係*を見出しで示し、見出し→理由→今日の一手→未確認条件の順に変更。
2. **旧：** 「自由な時間」QUEST3で仕事/家事/移動がほぼ同じ提案 → **新：** 仕事の予定・家事分担・移動頻度/所要時間という異なる初手。
3. **旧：** C3結果から面談へ戻っても「ライフプラン相談」一律表示 → **新：** C3結果の`consultTopic`（例：収入と働き方の選択肢）を引き継いで「この作戦を相談する」と表示。C2からの従来直接面談CTAは変更しない。**プレビューでは実際のLINE送信・予約なし。**

**重要な反証**：第2章に「住居費の確認対象」が無いケースで、最初の実ブラウザテストが汎用見出しへのフォールバックを検出。改善し、**「住まいで守りたいことと変えたいこと」を整理する目的地別の結果**を用意した。根拠がないのに「住居費が高い/削れる」とは言わない。その他の10以上の主ルートにも明示的な安全フォールバックを設けた。

## 4視点×各25点の赤入れ（採点は未実施）

**採点保留の理由**：4×25点の尺度は [PR #70 Draft 0.8](https://github.com/mudagiri/mudagii/blob/design/chapter3-v2-result-first-20261020/docs/CHAPTER3_V2_100POINT_CONTENT_GATE_AND_WEAK_RESULTS_DRAFT_08_20261021.md) に定義済みだが、実ユーザーと実予約のデータが無い段階で得点を補填するのは不当。

## 採用候補のリザルト表現

- **住まい×C2確認余地×近い期限**：「家賃を下げるより先に、今の住まいをいつまで使うか。」→ 現契約と希望時期を確認。住居形態は不明として扱う。
- **挑戦×C2未確定候補**：「第2章の『見直せるかも』は、まだ挑戦の元手じゃない。」→ 必要費用3項目を書く。候補額の現金化禁止。
- **教育費を守る×家族**：「今払っている教育費と、これから必要なお金は別の話。」→ 今/将来の支出を分ける。
- **老後×楽しみを守る**：「好きな時間を減らすことだけが、老後への準備じゃない。」→ 守りたい暮らしを書く。
- **収入増×社外依頼経験（本人申告）**：「仕事を増やす前に、『すでに頼まれたこと』を見てみよう。」→ 実績と時間を記録。適職/収益化可否は未判定。
- **資産形成×近い支払予定**：「増やすお金を選ぶ前に、近く使うお金を守ろう。」→ 予定の費用・時期を確認。投資商品や損失許容度を判定しない。
- **時間不足×家事**：「家のことを全部抱えないために、分けられる作業を探そう。」→ 一つ分担相談の候補を探す。
- **C2根拠不足**：本人が選んだ目標に応じた**確認候補**を表示し、`limitedEvidence`で未確認と分かるようにする。既知の支出額・比較差を作り込まない。
