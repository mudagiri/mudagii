# ムダギリ診断｜第2章リザルト V1.9 情報階層・RPG背景・余白のデザイン監査

日付：2026-10-13／対象：Draft PR #46 の隔離プレビュー。診断コア・正本データ・GAS API判定は変更しない。

## 指摘と根本原因
「背景がかなりシンプルな色なのに、ごちゃごちゃしている。ムダギリくんの世界観がちょこまか出てくる」。

UIの密度とRPGの世界観は別軸。既存画面は各セクションに金枠・発光・ラベル・カード背景が繰り返され、ヒーロー、宝箱、未来金額、JOB、敵、保障、面談、共有に同程度の注意を要求していた。特に同じ候補月額の再掲、5つの会話、12カテゴリ図鑑・8択の目標・複数の面談CTAが「戦果→理解→次の一手」を分断した。

## V1.9の3層情報設計
1. **主役（常時開示）**：QUEST CLEAR、月最大の未確定候補、全候補の金額・理由・確認行動、1/5/10年の仮定、4STYLEからの連続性、保障確認カード、ライフプラン相談。これらは詳細タップに隠さない。診断額は未確定であり、確定改善額を混ぜない。
2. **支え（やや落ち着いた表示）**：JOB・戦果数・確定改善額、節目でのみ話すムダギリくん。公式アートでギルドホール→戦利品→次の冒険をつなぎ、二次カードは低彩度・弱い枠にする。
3. **寄り道（本人が望むとき開示）**：12体の敵図鑑、行動の再確認、任意の8目標。全文は削除せずアクセシブルな `details/summary` に収納する。任意目標が未選択なら2つめの相談CTAは出さない。保障LINEは別目的の専用アクションとして保持。

「すべての情報を閉じる」は行わない。**未確定候補の内訳・根拠と保障理由は常時表示**という以前のUX合意を最優先する。

## 4視点の監査／反証条件

| 観点 | 実装の変更 | QA基準 | ユーザー検証で失敗とする例 |
|---|---|---|---|
| 行動経済学 | 最初の金額・理由・一手は開示、12カテゴリ完全図鑑だけを任意表示。装飾競合と選択肢の初期露出を減らす | 候補全件の内訳と未確定注記が初期表示、図鑑・8目標は初期閉鎖、主要CTAは初期可視 | 金額の意味や次に確認することを自発的に説明できない |
| 心理学 | ギルドホール・戦果・次の冒険を連続した風景で表現。ムダギリくんの会話は節目の2か所に限定 | 背景画像アセットが有効で、文字の読みにくさ・横はみ出しなし。古い保険を一律に否定しない | 物語が分断・煽り・押し売りに感じられる |
| マーケティング | ライフプラン相談CTAを一つのメインゲートに固定、目標に応じた別CTAは本人が選択した後だけ出す。保障は独立した明示相談 | 相談のplacement/topic/insuranceReviewを保持、LINE相談文・コードを損なわない | 相談目的が分からない、8択や詳細で迷って離脱する |
| バズ理論 | 派手な見せ場を月額戦果・10年シミュレーション・JOBに集中。共有カードは既存の匿名JOB/クリア情報に限定 | 共有へ家計金額・保険・医療情報を追加しない。通常のネイティブ画像共有を回帰 | 共有する場面が分からない／個人情報が漏れると不安になる |

## 実装差分
- `chapter2-v19-scene-css.ts`：公式3背景を用いた連続したRPG空間。枠線・影・タグ・色の抑揚を整え、本文は14px基準へ。
- `ResultScreenChapter2V32.tsx`：2つの会話節目に整理し、任意の図鑑・目標・次の一手を初期閉鎖。ただし常時見える候補の説明・LINEカードは保持。新CSSをV32の後に読み込む。
- `qa-chapter2-v32.ts`・`scripts/qa-chapter12-answercheck-browser.mjs`：会話数、初期露出の整理、12体のアクセス性、8目標の維持、背景素材、主要CTA、Chrome/WebKit×320/375/390/430pxを監査。

## リリース判定と残作業
コードとCIのPASSはデザインの「100点」やCV向上を保証しない。実機スクリーンショットを確認し、5〜8名のCognitive Pilotで「主役は何か」「説明が難しい部分」「違和感のある演出」「相談したくなるか」を検証する。今回の変更はDraftブランチだけであり、正式公開は別承認ゲート。LINE実送信→GASリード照合→実相談まで未確認。
