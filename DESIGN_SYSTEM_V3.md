# MUDAGIRI DESIGN SYSTEM V3 — RETRO RPG NATIVE

## Goal
A screenshot must be identifiable as ムダギリ診断 without logo/context. Avoid generic AI/SaaS visual language.

## Visual grammar
- Retro RPG grammar + modern mobile UX + finance readability.
- Game chrome: square/near-square windows, 2px light borders, hard 4px black shadow, command cursor `▶`.
- Finance layer: ordinary readable Japanese typography, clear yen values, simple inputs. Never force pixel font on long text/numbers.
- Mascot/enemies: pixel art only. UI labels are HTML text, not baked into sprites.

## Palette
- Ink #09090B
- Panel #111113
- Paper #F4F0DF
- MUDAGIRI yellow #FBBF24
- Battle red #EF4444 (rare)
- LINE green only on actual LINE action where needed.
No blue-purple gradients. No rainbow semantic cards.

## Banned patterns
- Gradient hero backgrounds
- Glassmorphism
- Repeated 24px rounded cards
- Emoji as primary enemy art
- Dashboard grids as the main result composition
- Pill badges everywhere
- Generic sparkle icons for emphasis
- Long AI-explainer copy

## Screen composition
- One screen = one event.
- Intro = mascot + hook + RPG command menu.
- Inputs = modern, fast, plain. Game chrome only around stage context.
- Battle = one enemy centered, one dialogue window, one decision.
- Result = vertical ending sequence, not dashboard: TITLE → SCORE → MONEY → PROTECTED → GOAL → UNRESOLVED → LINE.

## Copy rule
Game copy is short. Financial caveats are plain Japanese. Do not make serious disclosures into jokes.

## Acceptance criteria
1. No major screen is a stack of generic rounded cards.
2. Mode selection looks like a command menu, not pricing cards.
3. Battle reads as a game event in <1 second.
4. Result has one dominant number at a time.
5. Important finance text remains readable at 360px width.
6. Brand yellow is accent, not a full-screen wash.
